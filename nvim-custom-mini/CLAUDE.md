# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A deliberately minimal Neovim config for **Neovim 0.12+**. The core is **two plugins**
(`mini.nvim` + `nvim-treesitter`), plus two optional add-ons the user opted into:
`tokyonight.nvim` (theme) and `mason.nvim` (LSP server installer). The guiding
principle: everything that Neovim 0.12 can do natively is done natively, and the
plugin count is kept as low as possible. When adding or changing functionality,
prefer a built-in over a plugin, and prefer a `mini.nvim` module over a new
dependency — a new plugin is a real cost and should clear a high bar. The core is
designed to be droppable to one plugin (mini.nvim alone). See `README.md` for the
full rationale and the built-in-vs-plugin mapping table.

## No build / test / lint

This is a personal editor config, not a buildable project. There is no test suite,
linter, or build step. "Running" it means launching `nvim` with this config active
(it lives at `~/.config/nvim`, which is the working directory).

To sanity-check changes:
- `nvim --headless "+lua print('ok')" +qa` — confirms config loads without Lua errors.
- Inside Neovim: `:checkhealth`, `:checkhealth vim.lsp`, `:lsp` (inspect LSP clients),
  `:messages` (see startup errors), `:Inspect` (highlight/treesitter under cursor).
- Plugin management is via built-in `vim.pack`: `:lua vim.pack.update()` (or
  `<leader>pu`), `:lua vim.pack.del({ "name" })` to remove. The lockfile
  `nvim-pack-lock.json` is generated by vim.pack and **should be committed**.

## Architecture

`init.lua` sets leader keys and `require`s five modules in `lua/config/` **in a
fixed order** — `options → keymaps → autocmds → plugins → lsp`. `plugins` must run
before `lsp` (LSP relies on nothing from plugins, but `plugins` sets up filetypes/
treesitter that the editing experience depends on). Each file has a single concern:

- **`options.lua`** — all `vim.opt` settings, plus the global `vim.diagnostic.config`
  (diagnostic signs live here, not in `:sign-define`, which is removed in 0.12).
- **`keymaps.lua`** — global (non-plugin, non-LSP) keymaps, and the `float_term`
  helper that powers lazygit (`<leader>gg`) and the floating terminal (`<C-/>`)
  using only `nvim_open_win` + `jobstart` (no terminal plugin).
- **`autocmds.lua`** — editor autocmds (yank highlight, cursor restore, auto-mkdir,
  etc.) and the treesitter `indentexpr` wiring.
- **`plugins.lua`** — `vim.pack.add()` for the two plugins, then setup for **every
  enabled `mini.nvim` module** and treesitter parser installation. This is where
  most keymaps for pickers, git, files, and LSP navigation (`gd/gr/gI/gy`) live.
- **`lsp.lua`** — Mason setup + the `ensure` auto-install list, every language
  server (defined inline, no nvim-lspconfig), the
  `vim.lsp.enable({...})` list, the `LspAttach` autocmd (buffer-local LSP keymaps,
  inlay hints, document highlight, native completion, inline color swatches via
  `vim.lsp.document_color`, code lens via `vim.lsp.codelens`), a single global
  format-on-save autocmd, and the insert-mode Tab/S-Tab/CR completion+snippet keymaps.

### Key architectural conventions

- **Keymaps are split by origin, not by category.** LSP buffer-local keymaps
  (`K`, `<leader>ca`, `<leader>cf`, …) live in the `LspAttach` callback in
  `lsp.lua`. LSP *navigation* keymaps (`gd/gr/gI/gy`) are global in `plugins.lua`
  because they route through `mini.extra` pickers, not raw `vim.lsp.buf`. Everything
  else global lives in `keymaps.lua`. When adding a keymap, put it where its
  dependency lives.
- **`mini.nvim` is one repo but ~40 modules.** Each is enabled with its own
  `require("mini.xxx").setup()` in `plugins.lua`. Global handles (`MiniPick`,
  `MiniExtra`, `MiniFiles`, `MiniDiff`, `MiniIcons`) are set by these setups and
  are also whitelisted in `lua_ls` diagnostics globals — if you rely on a new
  `Mini*` global in config code, add it to that `globals` list in `lsp.lua`.
- **LSP is fully native (0.11/0.12).** Add a server by adding a
  `vim.lsp.config("name", {...})` block in `lsp.lua` **and** adding `"name"` to the
  `vim.lsp.enable({...})` list. A server only actually starts if its `cmd` is found
  on `$PATH`, so unused server definitions cost nothing.
- **Server binaries are installed by Mason** (`mason-org/mason.nvim`), set up at the
  top of `lsp.lua`. `mason.setup()` prepends Mason's `bin/` to `$PATH`, so servers
  installed via Mason are found by the native config with no `mason-lspconfig` bridge.
  The `ensure` list in `lsp.lua` holds the **mason package names** (e.g. `ts_ls` →
  `typescript-language-server`, `jsonls` → `json-lsp`) for the enabled servers and
  auto-installs missing ones on startup; keep it in sync when adding/removing a
  server, or manage interactively with `:Mason`. Manual install (brew/npm/etc.) still
  works too — Mason is a convenience, not a requirement.
- **Format-on-save is one global autocmd**, not per-client (a per-client one clears
  its own augroup on each attach, so only the last formatter would run). It formats
  with every attached client that can. Gate it with `vim.g.autoformat = false`
  (global, toggled by `<leader>uf`) or `vim.b[buf].autoformat = false` (per buffer).
- **UI toggles live under `<leader>u`** in `keymaps.lua` (wrap, spell, line numbers,
  diagnostics, format-on-save, diagnostic virtual-lines) — the LazyVim `<leader>u`
  convention. `<leader>uh` (inlay hints) is the exception: it's buffer-local in
  `lsp.lua` because it depends on the attached client.
- **Completion, snippets, comments, folds are all built-in.** Native
  `vim.lsp.completion` (autotrigger, enabled per-buffer in `LspAttach`),
  `vim.snippet` (Tab/S-Tab jump in `lsp.lua`), built-in `gc` commenting, and
  `vim.treesitter.foldexpr()` folds. Do not reach for nvim-cmp/blink/LuaSnip/
  Comment.nvim/nvim-ufo — the whole point is to avoid them.

### Special cases worth knowing

- **jdtls (Java) and angularls use a `cmd` *function*** rather than a static command
  list, because they need per-project computation: jdtls builds a per-project
  workspace dir under `~/.cache/nvim/jdtls/<project>` (a shared workspace corrupts
  on project switch) and auto-attaches Lombok if `~/.local/share/nvim/lombok.jar`
  exists; angularls points its probe locations at the *project's* `node_modules`.
- **Angular templates:** `*.component.html` is registered as the `htmlangular`
  filetype in `plugins.lua` so angularls (not the generic html LSP) owns it. Both
  `ts_ls` and `angularls` attach to `.ts` files on purpose.
- **Treesitter is archived but pinned to its `main` branch** (the 0.12-compatible
  rewrite) in `vim.pack.add`. A `PackChanged` autocmd (registered *before*
  `vim.pack.add`) runs `TSUpdate` on install/update. New languages need their parser
  added to the `want` list in `plugins.lua`.
